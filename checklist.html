Before you submit

The checklist

Every check on this page is one that a real task failed. Run it top to bottom. Each line links to the mistake it prevents.

1. The task you were given

Read your own prompts and ask what the page does when someone clicks it. If the answer is nothing, you built a document. The word dashboard in the Agent Objective does not change that.

The deliverable sits below the complexity bar

The tell is in your own golden: a search that comes back empty, a steering turn telling the agent to reach the page another way, and a deliverable that flags its own figures as unconfirmed.

The rules point at records the universe does not hold

2. What the conversation may not say

Read each of your turns and ask what is left for the agent to work out. Then read your negative criteria against the same turns and check each one is still reachable.

A steering turn that hands over the answer

Read each prompt beside the file it releases. Every number, name or conclusion that the file itself carries is a leak, however conversational it sounds.

A prompt that answers its own attachment

Read every turn-1 input as the agent will. If it tells you what a later turn wants, or what to do when a file arrives, you have it. Then read the deferred filenames cold: price_sheet_for_turn3.pdf fails, sheet_02.pdf is fine.

A deferred asset that announces its own turn

3. Milestones

Sort your milestone table by turn and read only the two fields. Turn 1 is opening unless the agent has genuinely been handed something new. Assets Delivered names input files the user hands over — never the .html the agent is about to write, and never a bare extension.

Modifier and Assets Delivered that do not match the turn

Two questions per row. Would this let the simulator move on while something the turn asked for is still undone? And can this turn actually produce what the clause demands, with nothing from later turns in hand?

Stopping rules that do not gate the turn

List the turn index of every milestone beside the prompts. Every prompt number appears at least once, and each milestone's turn is the turn whose prompt asks for what it describes.

A turn no milestone covers, or the same one written twice

4. A rubric that separates two runs

Count them. Negatives should be about a quarter of the set. Then check the sign is doing what you think: a negative criterion is a failure when it is Present, so if it reads like something a good run does, it is inverted and it will mark down your own golden.

A rubric that can only reward, never penalise

Walk the prompts line by line and write down which criterion owns each requirement. Then walk the criteria and point at the sentence in a turn that asks for each one. Anything with no partner on either pass is a finding.

A requirement nothing grades, and a criterion nothing asked for

Sort your criteria by weight and read them in order. The order should match the effort the task actually demands. Count the axes each one requires — tool or source coordination, reasoning depth, modality, discovery — and read off +5 for three or more, +3 for exactly two, +1 for one or none.

Weights that do not separate difficulty from lookup

Filter the objective block by Evaluation Target and count the Trajectory rows. Over five is the finding, and it is a count you can run in ten seconds.

More trajectory criteria than the Guidelines allow

Add up the weight of every criterion your Model A run failed and divide by the total objective weight. rubric_justifications.md records exactly which ones failed, so this is a number you can read off the folder before you submit.

A run that does not fail enough of the rubric

5. Criteria a correct run can pass

Grade the golden against every criterion as the last step before submitting. Separately, read the Desired Outcome clause by clause with the prompts beside it and mark every rule no turn asks for.

A criterion the golden itself fails

For every exact value, name the line, frame or field it comes from. For every criterion naming one item as the answer, ask whether the prompt or the inputs state the rule that picks it. For every criterion that names a step or section, go to that exact moment in your golden and confirm the values are visible there. Then read each one back and ask what wrong run still passes.

Criteria a correct run cannot pass, or a wrong one can

Filter by target and read the categories beside it. Agent Behavior and Tool Use always sit on Trajectory. Everything graded on the delivered file sits on Final Answer Artifact. Every subjective row is Task Completion.

Category and Evaluation Target filled with the wrong kind of value

For each criterion, name the one line of evidence that decides it. If another criterion is decided by the same line, you have a duplicate. A subjective criterion has to survive with its values stripped out — if nothing is left, it belonged in the objective block.

The same check written twice

6. The subjective block

Search the deliverable's filename across the subjective block and check every criterion returns a hit.

Subjective criteria that never name the file

Two sums before you submit. Count the rows — ten is the floor, not the target. Then compute the subjective share using absolute values, because negatives push the real figure above the naive one.

Too few criteria carrying too much weight

Cover the page and read the criterion again. If it only makes sense with your build in front of you, it is naming your text rather than a property.

Subjective criteria written from the finished page

7. Closing the task

Take every value the golden asserts that no criterion grades and point at the source line it came from. Ungraded values are where this hides, because nothing else in the task checks them. Then search the golden for every sentence containing a total, a count or a recommendation and check it against the tables on the same page.

The golden states something its own sources contradict

After every revision turn, search the artifact for the value, the label and the name that moved, and read each hit in place.

A revision that leaves the old wording standing

Five lists, side by side, in five minutes. Archive contents against the filenames the prompts name. The run picker reading 1/1 and not 0/1. Every filename character for character. The prompts and criteria read straight through as a grader would. User markers in the golden transcript against populated prompts.

The five minute close-out nobody runs
