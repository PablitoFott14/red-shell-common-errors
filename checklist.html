Before you submit

The checklist

Every check on this page is one that a real task failed. Run it top to bottom. Each line links to the mistake it prevents.

1. The task you were given

Read your own prompts and ask what the page does when someone clicks it. If the answer is nothing, you built a document. The word dashboard in the Agent Objective does not change that: the agent never sees the Agent Objective, only your prompts and inputs.

The deliverable sits below the complexity bar

The tell is in your own golden: a search that comes back empty, a steering turn telling the agent to reach the page another way, and a deliverable that flags its own figures as unconfirmed.

The task relies on records the universe does not hold

2. What the conversation may not say

Read each of your turns and ask what is left for the agent to work out. Then read your negative criteria against the same turns and check each one is still reachable.

A steering turn that hands over the answer

Read each prompt beside the file it releases. Every number, name or conclusion the agent is meant to read out of that file is a leak, however conversational it sounds.

A prompt that answers its own attachment

Read every turn 1 input as the agent will. If it tells you what a later turn wants, or what to do when a file arrives, you have it. Then read each deferred filename cold: price_sheet_for_turn3.pdf fails, price_sheet.pdf costs points, sheet_02.pdf is fine.

A deferred asset that announces its own turn

3. Milestones

Sort your milestone table by turn and read only Modifier and Assets Delivered. Every modifier is one of the four, and turn 1 is never deferred_asset or revision: nothing can be deferred into the opening turn, and nothing has been delivered yet to revise. Assets Delivered names, by full filename, the files the user hands over at that turn, every deferred file included, and never the .html the agent is about to write.

Modifier and Assets Delivered that do not match the turn

Two questions per row. Would this let the simulator move on while something the turn asked for is still undone? And can this turn actually produce what the clause demands, with nothing from later turns in hand?

Stopping rules that do not gate the turn

List the turn index of every milestone beside the prompts. Every prompt number appears at least once, and each milestone's turn is the turn whose prompt asks for what it describes. Then sort the rows by intent text: two identical neighbours are a duplicate.

A turn no milestone covers, or the same one written twice

4. A rubric that separates two runs

Count them. Negatives should be about a quarter of the set. Then check the sign is doing what you think: a negative criterion is a failure when it is Present, so if it reads like something a good run does, it is inverted and it will mark down your own golden.

A rubric that can only reward, never penalise

Walk the prompts line by line and write down which criterion owns each requirement. Then walk the criteria and point at the sentence in a turn that asks for each one. Anything left without a partner on either pass is this error.

A requirement nothing grades, and a criterion nothing asked for

Sort your criteria by weight and read them in order. The order should match the effort the task actually demands. Count the axes each one requires: tool or source coordination, reasoning depth, modality, discovery. Then read off +5 for three or more, +3 for exactly two, +1 for one or none.

Weights that do not separate difficulty from lookup

Filter the objective block by Evaluation Target and count the Trajectory rows. Over five is the error, and it is a count you can run in ten seconds.

More trajectory criteria than the Guidelines allow

List every criterion Model A failed, in both blocks: each positive rated Not Present and each negative rated Present. Add up their weights, ignoring the minus sign, and divide by the total weight of every criterion in the task, counted the same way. Your failure justifications already name every one of them, so this is a number you can work out before you submit.

A run that does not fail enough of the rubric

5. Criteria a correct run can pass

Grade the golden against every criterion as the last step before submitting. Separately, read the Desired Outcome clause by clause with the prompts beside it and mark every rule no turn asks for.

A criterion the golden itself fails

For every exact value, name the line, frame or field it comes from. For every criterion naming one item as the answer, ask whether the prompt or the inputs state the rule that picks it. For every criterion that grades where a value came from, check whether a second source carries it. For every criterion that names a step or section, go to that exact moment in your golden and confirm the values are visible there. Then read each one back and ask what wrong run still passes.

Criteria a correct run cannot pass, or a wrong one can

Filter by target and read the categories beside it. Agent Behavior and Tool Use always sit on Trajectory. Everything graded on the delivered file sits on Final Answer Artifact. Every subjective row is Task Completion.

Category and Evaluation Target filled with the wrong kind of value

For each criterion, name the one line of evidence that decides it. If another criterion is decided by the same line, you have a duplicate. A subjective criterion has to survive with its values stripped out. If nothing is left, it belonged in the objective block.

The same check written twice

6. The subjective block

List the files the task ships. If there is more than one, read down the subjective block: every criterion has to contain one of those filenames, and any row without one is this error.

Subjective criteria that never name the file

Two checks before you submit. Count the rows: ten is the floor, not the target. Then add up the subjective weights without their signs and divide by the same sum over every criterion in the task. Anything over 0.30 is over the cap.

Too few subjective criteria, or too much weight on them

Search your prompts for every heading, label or column title a subjective criterion quotes. If no prompt contains it, you chose it, and the criterion is grading your wording. If a prompt does, it belongs in the objective block.

Subjective criteria that require your golden's wording

7. Closing the task

Take every value the golden asserts that no criterion grades and point at the source line it came from. Then search the golden for every sentence containing a total, a count or a recommendation and check it against the tables on the same page.

The golden states something its own sources contradict

After every revision turn, search the artifact for the value, the label and the name that moved, and read each hit in place.

A revision that leaves the old wording standing

Five checks, in five minutes. The artifacts archive listed beside the filenames the prompts name. The run picker, which should read “Preferred: 1/1 selected”, not 0/1. Every filename in the prompts, both archives and the criteria, read character for character. The prompts, milestones and criteria read straight through as a grader would, marking every clause you had to read twice. The golden transcript, which should carry every prompt the task ships, the last one included.

The five minute close out nobody runs
