The deliverable sits below the complexity bar

costs points
Complexity Bar
1

What the issue is

The deliverable does not clear the complexity bar's floor for the type it is meant to be. The usual case is a styled static page with no script, no control, no state and no linked views, while the Agent Objective calls it a dashboard. Nothing in any prompt asks for interaction, so the page comes out a document.

2

Why it matters, and what the project expects

A page that does nothing when clicked clears neither the interactive HTML floor nor the dashboard floor. It is a document, the lowest priority deliverable on the bar, so the task falls short of what the client asked for however good the reasoning underneath is. The deliverable is set by the prompts at scenario stage, so it cannot be patched later.

Attempter GuidelinesComplexity Bar
Interactive HTML: Interaction that actually works: controls that respond, state that changes, filters or navigation. A styled static page does not qualify. Dashboard: Several linked views over data the model extracted itself. One chart is not a dashboard.

Both are P0 floors. A page with no control and no state is a document, whatever the objective calls it.

Attempter Guidelines1.3 Defining the Draft History
The Draft History (Agent Objective, Desired Outcome, Multimodal Upload) is not embedded in the agent by default. The prompts and multimodal context are the only context the agent has access to, so never assume a requirement is in play just because you wrote it down here. Anything you expect the agent to produce must be explicitly requested through the prompts, turn by turn, or it cannot be graded.

Calling it a dashboard in the Agent Objective asks for nothing. Only a prompt can.

3

How to recognise it in your own task

Read your own prompts and ask what the page does when someone clicks it. If the answer is nothing, you built a document. The word dashboard in the Agent Objective does not change that: the agent never sees the Agent Objective, only your prompts and inputs.

5

What to do instead

Pick the deliverable type before prompt 1 and check it against the bar's floor for that type. If the data the agent will gather would support a sort, a filter or two linked views, write the prompt that asks for them.

The issue, in this task
The setup
Three turns; the Agent Objective calls the deliverable a dashboard, and 14 orders and 222 order lines sit behind the five products it covers.
Where the issue shows up here
ada_list.html ships with no script tag, no button, no filter and no navigation within the page: 8,959 characters of markup around nine embedded images.
Why that is wrong
What the task produces is sections, a table and figures the text refers to: a document, the lowest priority deliverable on the bar. The data for a real dashboard was already gathered, so a sortable buy list, a filter that hides what Fresh does not stock, and a view setting each usual product beside its alternative with the order counts that decide between them were all within reach. No prompt asked for any of them.
What it should have said
Ask for it in the prompt: "put the buy list in a table I can sort by aisle or by price, and give me a toggle that hides anything Fresh doesn't stock."

Agent Objective
Winslow Achebe is picky about grocery brands, and this time, Adaeze is the one going to the store. While he was writing his shopping list, someone at the office pushed some cheaper lookalike products on him. He needs one local HTML dashboard, 'ada_list.html ', that Ada can use at the store, where his sticky list becomes a detailed shop sheet (brand, product, price, amount, and product picture), and it includes a clear comparison of the tip products against what he already buys on Amazon Fresh, with a fixed KEEP TIP or SKIP TIP call.
Every prompt the task ships
Turn 1
Ada called; she's going to the store after work, and I was making my list for her when I was told I could change some products. I got some pics of the products (proteinbars.png, gfacts.png, and gimage.png), and I need to create a comparison table for the products I usually buy, coz I'm really picky about my things. I also need to create an "ada_list.html" where I need to have the items from the list I uploaded, with the amounts I usually buy. It should be detailed, like brand, price, size, and a pic of them, so Ada doesn't get them wrong.
Turn 2
I only asked for one HTML. I need you to check the swaps with this rule: KEEP TIP only when the new product is lower priced than my usual and organic. Protein should be at least 10g, and the OJ should have Calcium and vitamin D. Otherwise, SKIP TIP.
Turn 3
Okay, that's better for comparison, but you didn't really research either. Also, the page should be focused on the list first, and you are asking me to write the data you have. It needs brand, price, size, amount, and a product picture. Don't invent it you have the data.
