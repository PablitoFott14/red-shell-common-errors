All mistakes · Section 1 · The task you were given

The deliverable sits below the complexity bar

fails the task
Complexity Bar

What the project asks for gl · Complexity Bar

“Raising the complexity standard from Blue Shell has been one of the clearest and most consistent client requirements.” Interactive HTML needs “interaction that actually works: controls that respond, state that changes, filters or navigation. A styled static page does not qualify.” A dashboard needs “several linked views over data the model extracted itself. One chart is not a dashboard.” Both are P0.

What the mistake is

The task ships a styled static page — no script, no control, no state, no linked views — while the Agent Objective calls it a dashboard. The scenario and the data behind it are usually strong. Nothing in any prompt asks for interaction, so the page comes out a document.

How to recognise it in your own task

Read your own prompts and ask what the page does when someone clicks it. If the answer is nothing, you built a document. The word dashboard in the Agent Objective does not change that.

What to do instead

Pick the deliverable type before prompt 1 and check it against the bar's floor for that type. If the data the agent will gather would support a sort, a filter or two linked views, write the prompt that asks for them.

Why it costs you

The bar is explicit that a styled static page is not interactive HTML, and that a dashboard needs several linked views over data the model extracted itself. A document is the lowest priority deliverable on the table, so the task scores below where the client wants it however good the reasoning underneath is. It is a scenario-stage decision, so it cannot be patched later.

Turn 1
Ada called; she's going to the store after work, and I was making my list for her when I was told I could change some products. I got some pics of the products (proteinbars.png, gfacts.png, and gimage.png), and I need to create a comparison table for the products I usually buy, coz I'm really picky about my things. I also need to create an "ada_list.html" where I need to have the items from the list I uploaded, with the amounts I usually buy. It should be detailed, like brand, price, size, and a pic of them, so Ada doesn't get them wrong.
What is wrong
ada_list.html ships with no script tag, no button, no filter and no in-page navigation: 8,959 characters of markup around nine embedded images.
Why it is wrong
What the task produces is sections, a table and figures the text refers to — a document. The data for a real dashboard was already gathered: a sortable buy list, a filter for Fresh versus not-on-Fresh rows, or a view showing each usual product against its alternative with the order counts that decide between them were all available and none were asked for.
What it should have said
Ask for it in the prompt: "put the buy list in a table I can sort by aisle or by price, and give me a toggle that hides anything Fresh doesn't stock."
