All mistakes · Section 4 · A rubric that separates two runs

A run that does not fail enough of the rubric

fails the task
Difficulty
1

What the issue is

The task is built, the rubric is written, and the Model A run passes most of it. From inside the task nothing looks wrong: the criteria are sound and the run does fail some. What gives it away is the arithmetic.

2

Why it matters, and what the project expects

Every task has to be hard enough that the Model A trajectory clearly fails at least 50% of the rubric score. That is a hard client requirement, not a target. A run that sails through most of the set is not separating a strong model from a weak one, and the data is worth less.

Attempter GuidelinesHard Client Requirements for Every Task
Model A has to fail: Enough difficulty that the Model A trajectory clearly fails at least 50% of the final rubric score, with failures that materially affect task completion and the user experience. If the desired outcome is reached too easily, increase the complexity.

A hard requirement with a number in it. Add up the failed weight and divide.

Attempter Guidelines1.2 Building the Idea
The idea is the foundation of your entire task; if it's rushed or underdeveloped, the agent will complete the task too easily, and you won't be able to meet the core requirement that the agent must fail at least 50% of the final rubric score.

The fix is always a harder scenario, never heavier weights on the same rows.

3

How to recognise it in your own task

Add up the weight of every criterion your Model A run failed and divide by the total objective weight. rubric_justifications.md records exactly which ones failed, so this is a number you can read off the folder before you submit.

4

Real tasks where this happened

One real task in this project is carrying it. They are evidence that it is real and something to practise spotting it on, not a second version of the rule. Open one and it expands here, with the point on the left and the task's own fields on the right. Escape closes it.

5

What to do instead

Under 50% means the scenario is too easy. The fix is a harder scenario, putting the sources in disagreement, never heavier weights on the same rows, and never padding the set.

The issue, in this task
The setup
The page has to reconcile a May quote against the current one, price the financing and lay out two purchase paths.
Where the issue shows up here
Thirteen of the thirty-eight criteria carry a failure justification, but nine of those sit at weight 3 and only three at weight 5, while ten of the twenty-five criteria the run passed sit at weight 1.
Why that is wrong
The run failed a third of the criteria and still cleared only 43.0% of the objective weight, under the 50% the client requires. The set spends its weight on rows a competent run always gets, so the failures that do happen cannot add up.
What it should have said
Weight each criterion by the reasoning it needs, so the difficulty sits where the failures are: "The oven payment is 406.59 a month, being 19,702.00 financed at 8.75% APR over 60 months" is a 5, and a criterion restating a single value the source states outright is a 1.
The rules it breaks
