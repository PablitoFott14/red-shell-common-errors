All mistakes · Section 5 · Criteria a correct run can pass

Criteria a correct run cannot pass, or a wrong one can

costs points
Rubric Criteria - Overall Rubric Quality
1

What the issue is

A criterion narrower than its source, so a run that got it right still fails it. Four shapes recur. Pinning an exact figure the source leaves open. Locking one of several defensible answers when nothing states the rule that picks it. Grading which route a value came from when two sources carry it. Scoping to a step or section, then requiring values that live elsewhere. And the mirror image, a criterion looser than its source: a run carrying the right answer plus the wrong ones still passes.

2

Why it matters, and what the project expects

The rubric exists to separate a correct run from an incorrect one. A criterion a correct run cannot satisfy marks down the runs that did the work, and it usually catches your own golden, because the golden followed the evidence while the criterion followed your memory. A criterion with no ceiling lets a run that also took the distractors pass, so the traps the task was built around cost nothing.

Attempter Guidelines5.1 Rubric Fundamentals
Intent focused: Grade whether the model satisfied the actual user request and scenario intent. Since these are objective rubrics, only requirements that can be evaluated objectively from the scenario should be included.

If the scenario does not settle it, it cannot be graded objectively.

QC spec appendixRubric Quality Definitions · Overfitting and Underfitting
Overfitting: Criteria that are overly specific, inflexible or too rigid - they incorrectly reject a subset of valid implementations. Underfitting: Criteria that are overly broad, permissive or loose - they accept valid implementations, but also incorrectly accept invalid implementations too.

The two halves of this error, and both are Moderate issues. Pinning a value the source leaves open is overfitting; a criterion with no ceiling is underfitting.

Attempter Guidelines5.1.2 Stacked Rubrics (OR Logic)
Do not use OR to hedge uncertainty. If you are unsure which answer is right, the GTFA is not settled and the planning is weak.

Where several answers are defensible, settle it in the prompt or grade the shape of the answer.

3

How to recognise it in your own task

For every exact value, name the line, frame or field it comes from. For every criterion naming one item as the answer, ask whether the prompt or the inputs state the rule that picks it. For every criterion that grades where a value came from, check whether a second source carries it. For every criterion that names a step or section, go to that exact moment in your golden and confirm the values are visible there. Then read each one back and ask what wrong run still passes.

4

Real tasks where this happened

Three real tasks in this project are carrying it. They are evidence that it is real and something to practise spotting it on, not a second version of the rule. Open one and it expands here, with the point on the left and the task's own fields on the right. Escape closes it.

5

What to do instead

If you cannot name the source, grade the pattern instead of the value. Where several answers are defensible, grade the shape of the answer, or state the rule that picks one in a prompt, which means running both legs again. Where two sources carry a value, grade that it was retrieved, not which door it came through. Where the values sit outside the step or section the criterion names, scope it to where they are, or to the whole artifact. Where a run with an extra row survives, add the bound: exactly, only, between.
