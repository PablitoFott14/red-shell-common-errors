The Scenario field describes a different task

fails the task
Rejected at QC before the rubric is read

What the project asks for gl §1

The scenario, the category and the universe are assigned parameters. The prompt must not drift away from the assigned task parameters, and a build that does is rejected before the rubric is read.

What the mistake is

The Scenario on file is not the task you built. Everything downstream — prompts, Draft History, milestones, criteria, golden — is one scenario, and the Scenario field is another, often with a Required Output line naming a deliverable the task never produces.

How to recognise it in your own task

Open the Story Draft step and read the Scenario field out loud against prompt 1. If the person, the deliverable or the Required Output line do not match, you have it.

What to do instead

Read the Scenario back before you write prompt 1, and again as the last check before you submit. Where the two disagree, stop and settle which one is right — never ship both.

Why it costs you

Scenario, category and universe are assigned parameters. You cannot change them, and a task that drifts from any of them is rejected however well it is written. When only the field is stale the task is fine, but nobody downstream can tell which of the two is real, so the reviewer has to escalate instead of scoring. When the drift is genuine it is fatal.

What is wrong
Scenario: "There is an ecobee in the hallway and an argument in a text thread going back to 2023", with a Required Output line asking for six Dixie Electric bills plotted against degree days for Hattiesburg.
Why it is wrong
Nothing else in the folder is about thermostats or electricity bills. A reviewer opening the task cannot tell whether the contributor built the wrong scenario, whose penalty is rejection, or whether the export carried stale text into an otherwise correct task, whose penalty is nothing. Only the platform settles it, so the task stalls on a field nobody checked.
What it should have said
Open the Story Draft step, read the Scenario field and make it describe the task you built: the deliverable, the person, and the Required Output line that matches prompt 1.
