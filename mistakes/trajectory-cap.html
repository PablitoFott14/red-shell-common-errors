All mistakes · Section 4 · A rubric that separates two runs

More trajectory criteria than the Guidelines allow

costs points
Rubric Criteria - Overall Rubric Quality
1

What the issue is

More than five criteria whose Evaluation Target is Trajectory. They are usually good criteria: the agent opened the image, it reached the record before applying it, it did not act on the file that was out of scope. Because each reads well alone, the count creeps up unnoticed.

2

Why it matters, and what the project expects

The Guidelines cap trajectory rubrics at five, minimum zero, and say to focus on the last response. Past that the set stops grading the deliverable and starts grading the route, and the same evidence usually appears twice: once as a trajectory criterion about the read, once as an artifact criterion about the value it produced.

Note This corrects the previous version of this course, which asked for more trajectory weight without mentioning the cap. The cap arrived with Guidelines v3 on 10 September 2026, so a habit formed before then is now over it.

Attempter Guidelines5.4 Category & Evaluation Target
The agent's reasoning path, Trajectory: An identification, a dependency order, a piece of restraint. The intent it pursued, never a named tool call.

Trajectory is a narrow target. Most of what feels like trajectory is really the artifact.

3

How to recognise it in your own task

Filter the objective block by Evaluation Target and count the Trajectory rows. Over five is the error, and it is a count you can run in ten seconds.

4

Real tasks where this happened

One real task in this project is carrying it. It is evidence that it is real and something to practise spotting it on, not a second version of the rule. Open it and it expands here, with the point on the left and the task's own fields on the right. Escape closes it.

5

What to do instead

Keep at most five, and keep the ones only the run can show: a load bearing read of the media, a dependency order, a piece of restraint. Drop the rest, moving any value they carry into an artifact criterion if none checks it yet.

The issue, in this task
The setup
The deliverable is energy_audit.html, which splits a household's electricity bill between two flatmates. The objective block runs to 46 criteria, and criteria 33 to 42 all target Trajectory.
Where the issue shows up here
Ten criteria target Trajectory, twice the cap of five.
Why that is wrong
Several of the ten grade a route whose result is already graded on the page. Criterion 39, that the agent checks the file opens and runs, sits beside criterion 1, which grades that energy_audit.html loads and operates. Criterion 36, the 32 metered days taken from the statement's own evidence, sits beside criterion 7, which grades that the page sums exactly those 32 days. Criterion 40, the payment history found in the household's records, sits beside criterion 26, which grades how the page attributes those payments. Criterion 33 asks only that the agent queries a connected application, which almost any run does.
What it should have said
Drop 33, 36, 39 and 40, whose results the page criteria already grade, and fold criterion 34's two values, museum hours of 8 to 3 and a camp ending on 3 August 2026, into an artifact criterion if none checks them yet. That keeps five that only the run can show: 35, the absence dates taken from a dated record; 37, the handwritten log read from the photographs; 38, the rate card read off pages with no text layer; 41, the baseline taken from individual hours; and 42, the negative for acting on the refrigerator labels before the turn that hands them over.
