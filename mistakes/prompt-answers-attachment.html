A prompt that answers its own attachment

fails the task
Multi-Turn - Simulator Answer Leak

What the project asks for gl §3 · spec · Multi-Turn - Simulator Answer Leak

A prompt “states the policy directly, removing the work you intended to grade” the moment it carries what the attachment was there to make the agent read. The rule covers every turn you write as the user, and it treats a count as a value.

What the mistake is

A user prompt releases a file and states the value the file exists to make the agent read: how many items are in the photograph, what the total comes to, which of two documents is current. It sits in the same sentence that hands over the asset, written as helpful context by someone who has already looked at the file.

How to recognise it in your own task

Read each prompt beside the file it releases. Every number, name or conclusion that the file itself carries is a leak, however conversational it sounds.

What to do instead

State the requirement — the plates lie flat, the figure has to be the current one — and leave the value to the attachment.

Why it costs you

The no-leak rule covers every turn you write as the user, and it treats a count as a value — the spec's own failing example is “there are five receipts”. Once the value is in the prompt the attachment is decoration: no criterion that depends on reading it can separate a run that opened the file from one that did not.

What is wrong
"Sorted the plates, the photo is fine to use now. There are five big ones and one small one, and they need to be stored flat somewhere in the unit."
Why it is wrong
Counting five large plates and one small one out of that photograph is the read the deferred asset exists to force, and the stack at the back of the frame is exactly what a model gets wrong. With the count in the prompt the photograph settles nothing, and because no criterion in the set sizes the shelf either, a run that never opens the file passes the whole task.
What it should have said
"Sorted the plates, the photo is fine to use now. They need to be stored flat somewhere in the unit, not stood on edge. Add that into the HTML rather than starting over."
