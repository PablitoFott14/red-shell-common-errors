2.2A Leg A prompt that answers its own attachment

Fails the taskMulti-Turn - Simulator Answer Leak

The mistake

A Leg A prompt that hands Model A a file also states what the file exists to make it read, such as a count or which document is current. The same words in Leg B leak it to Model B too.

Do this instead

State the requirement and leave the value to the file, then run both legs again.

Catch it in your own task

Read each prompt beside the file it hands over, in both legs: any value the model should read from that file is a leak.

Where the correct guidance is written

Section titles as they print, so you can search for them in the document.

QC spec · Multi-Turn - Simulator Answer Leak

One or more user turns supply a value, count, position, or conclusion (see notes for exceptions) the agent was supposed to derive from the multimodal inputs

Any user turn, in either leg. A count is a value.

Guidelines · 7.1 What Changes from Leg A

The same intent expressed the same way, and the same persona from first turn to last.

Unchanged in Leg B, so the turn that hands Model B the file repeats the value.

Why it matters

The no leak rule covers every turn you type, in Leg A and in Leg B, and QC treats a count as a value: one of its own failing examples is “there are five receipts”. Once the value is in a prompt, the attachment is decoration: no criterion that depends on reading it can separate a run that opened the file from one that did not, for Model A or for Model B.

How it breaks the standard

That count is the read IMG_4392 exists to force, so neither model has to open the photo to pass.

What it should have been

The same turn without the count: "They need to be stored flat somewhere in the unit, not stood on edge."
