A prompt that answers its own attachment

fails the task
Multi-Turn - Simulator Answer Leak
1

What the issue is

A user prompt releases a file and states the value the file exists to make the agent read: how many items are in the photograph, what the total comes to, which of two documents is current. It sits in the same sentence that hands over the asset, written as helpful context by someone who has already looked at the file.

2

Why it matters, and what the project expects

The no leak rule covers every turn you write as the user, and it treats a count as a value: one of the spec's own failing examples is “there are five receipts”. Once the value is in the prompt, the attachment is decoration: no criterion that depends on reading it can separate a run that opened the file from one that did not.

Treats the multimodal inputs as decorative.

One of the marks of a weak prompt in the Guidelines' own table. A value stated beside the file makes the file decorative: a run can pass without opening it.

QC specMulti-Turn - Simulator Answer Leak
One or more user turns supply a value, count, position, or conclusion (see notes for exceptions) the agent was supposed to derive from the multimodal inputs (e.g. "the total is 412.75", "there are five receipts", "it's the third image", "you missed the discount rule").

A count stated in the sentence that attaches the file fails, however late the turn comes.

3

How to recognise it in your own task

Read each prompt beside the file it releases. Every number, name or conclusion the agent is meant to read out of that file is a leak, however conversational it sounds.

4

Real tasks where this happened

One real task in this project is carrying it. It is evidence that it is real and something to practise spotting it on, not a second version of the rule. Open it and it expands here, with the point on the left and the task's own fields on the right. Escape closes it.

5

What to do instead

State the requirement, that the plates lie flat or that the figure has to be the current one, and leave the value to the attachment.

The issue, in this task
The setup
IMG_4392 is held back from turn 1 and released at turn 2 so the agent has to count and measure the plates before sizing a shelf for them.
Where the issue shows up here
"Sorted the plates, the photo is fine to use now. There are five big ones and one small one, and they need to be stored flat somewhere in the unit."
Why that is wrong
Counting five large plates and one small one out of that photograph is the read the deferred asset exists to force, and the stack at the back of the frame is exactly what a model gets wrong. With the count in the prompt the photograph settles nothing, and because no criterion in the set sizes the shelf either, a run that never opens the file passes the whole task.
What it should have said
"Sorted the plates, the photo is fine to use now. They need to be stored flat somewhere in the unit, not stood on edge. Add that into the HTML rather than starting over."
