Modifier and Assets Delivered that do not match the turn

fails the taskMost common right now
Milestones - Milestone Annotations · Milestones - Continuation Criteria & Assets
1

What the issue is

Modifier and Assets Delivered do not describe the turn: deferred_asset or revision on an opening turn, none used as a modifier, the agent's own deliverable listed as a delivered asset, a deferred file that no row lists, or a bare extension where a filename belongs.

2

Why it matters, and what the project expects

The simulator reads the modifier to decide how it drives the turn, and the assets field to know what arrives when. A wrong label changes the conversation the task actually runs: a revision that revises nothing, a deferred file that was attached from the start, a file handed over at a later turn that no row lists, so a replay never delivers it. Most of these cost points. The last one fails the task outright, because the QC spec requires Assets Delivered to list every deferred file.

Attempter Guidelines6.1 What a Milestone is Made of?
Modifier: What this turn does to work that already exists. One of the four in section 6.3. Assets delivered: Files handed over at this turn, or empty.

Assets delivered means files the user hands over, never the file the agent is about to write.

Attempter Guidelines6.3 Modifiers
Modifiers define what each turn does to the state of the task. They are not labels for how a prompt sounds but for how that turn changes, extends, or depends on work that already exists. opening: The first turn and any later turn that adds a new requirement without touching work already delivered. revision: Something already delivered changes.

The first turn is opening by definition, and a revision needs delivered work to change. On turn 1 there is none.

QC specMilestones - Milestone Annotations
This dimension flags any errors in: Turn, Modifier, Assets, and Continuation Criteria labeling.

The four label fields are graded on their own, separately from the intent text.

QC specMilestones - Continuation Criteria & Assets
Also fails where a deferred asset was handed over during the conversation but is absent from assets_delivered, or is listed but missing from input_files/.

Name every deferred file on the turn it arrives, and make sure the file is in the input files. Missing either one fails the task.

3

How to recognise it in your own task

Sort your milestone table by turn and read only Modifier and Assets Delivered. Every modifier is one of the four, and turn 1 is never deferred_asset or revision: nothing can be deferred into the opening turn, and nothing has been delivered yet to revise. Assets Delivered names, by full filename, the files the user hands over at that turn, every deferred file included, and never the .html the agent is about to write.

4

Real tasks where this happened

Three real tasks in this project are carrying it. They are evidence that it is real and something to practise spotting it on, not a second version of the rule. Open one and it expands here, with the point on the left and the task's own fields on the right. Escape closes it.

5

What to do instead

Set each modifier from the turn's effect on delivered work: opening for a new ask, deferred_asset only when a file actually arrives, revision only when delivered work changes. Then fill Assets Delivered with the full filename of every file the user hands over at that milestone's turn, and check every deferred file appears on the turn it arrives. A turn that hands over nothing correctly carries none.
