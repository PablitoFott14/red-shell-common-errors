Modifier and Assets Delivered that do not match the turn

costs pointsMost common right now
Milestones - Milestone Annotations

What the mistake is

The two fields beside the intent line do not describe what the milestone covers: deferred_asset or revision on an opening turn, none used as a modifier, the agent's own deliverable listed as a delivered asset, or a bare extension where a filename belongs.

How to recognise it in your own task

Sort your milestone table by turn and read only the two fields. Turn 1 is opening unless the agent has genuinely been handed something new. Assets Delivered names input files the user hands over — never the .html the agent is about to write, and never a bare extension.

What to do instead

Set each modifier from the turn's effect on delivered work: opening for a new ask, deferred_asset only when a file actually arrives, revision only when delivered work changes. Then fill Assets Delivered from that milestone's own sub-intent with real filenames. A behavioural or informational sub-intent correctly carries none.

Why it costs you

The simulator reads the modifier to decide how it drives the turn, and the assets field to know what arrives when. A wrong label changes the conversation the task actually runs: a revision that revises nothing, a deferred file that was attached from the start, an attachment that never reaches the agent because no milestone asked for it. It is two fields and a five minute pass, which is why it is worth making a habit.

What the project says

The rules this breaks, quoted from the documents in Project Resources. Section titles are the ones printed in the document, so you can go and read the whole thing around them.

Attempter Guidelines6.1 What a Milestone is Made of?
Modifier — What this turn does to work that already exists. One of the four in section 6.3. Assets delivered — Files handed over at this turn, or empty.

Assets delivered means files the user hands over, never the file the agent is about to write.

Attempter Guidelines6.3 Modifiers
Modifiers define what each turn does to the state of the task. They are not labels for how a prompt sounds but for how that turn changes, extends, or depends on work that already exists. opening — The first turn and any later turn that adds a new requirement without touching work already delivered. revision — Something already delivered changes.

Turn 1 is opening unless something was genuinely handed over. Nothing has been delivered yet to revise.
