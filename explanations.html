The mistakes that keep costing tasks in this project, each shown in real tasks where it happened. The slides teach the standard; each entry here quotes where it is written, takes the examples apart, and ends with how to catch the mistake and what to do instead.

Each issue opens with its cost: 🔴 Fails the task, 🟠 Fails a client CORE standard or 🟡 Costs points. Examples are numbered across the course, the same on the slides and in the viewer.

How to use this

Read the sections for the step you are on. They follow the part of the task, not the build order, and the earlier the step, the more a fix costs:

Step in the Guidelines Sections If you get it wrong
1 Planning the Agent Task, 2 Setting Up the Run 1; 2, for the input folder and the opening prompt Run both legs again
3 Task Runner - Leg A 2, for each follow up you send Model A Run both legs again
5 Objective Rubrics 4; 5 Rewrite in place, or run both legs again if the fix changes a prompt or Model A fails under half the weight
6 Milestones 3 Rewrite in place, before Leg B
7 Golden Solution - Leg B 2, for each turn you send Model B; 5, for the golden passing every objective criterion; 7 A Leg B cleanup turn to Model B before you complete Leg B, or Leg B again for a hint that leaks
8 Subjective Rubric Block 6 Rewrite in place
Before you submit 7, the close out Fix in place

One habit prevents most of what follows: open the files, then write.

1. The Foundations Every Task Must Get Right

Two decisions made before prompt 1 that cannot be repaired afterwards. Each one is cheap to check and expensive to get wrong.

1.1 The deliverable sits below the complexity barSee it in the viewer

🟠 Fails a client CORE standard

The deliverable misses its type's complexity floor. Typically the Agent Objective says dashboard, no prompt asks for interaction, and the page ships static.

Where the correct guidance is written

Guidelines · Complexity Bar

“Interactive HTML: Interaction that actually works: controls that respond, state that changes, filters or navigation. A styled static page does not qualify. Dashboard: Several linked views over data the model extracted itself. One chart is not a dashboard.”

Both are P0 floors.

Guidelines · 1.3 Defining the Draft History

“The Draft History (Agent Objective, Desired Outcome, Multimodal Upload) is not embedded in the agent by default.”

So only a prompt can ask for a dashboard.

Example 1 (🔗Open in the viewer)

The task. The Agent Objective calls it a dashboard, over 14 orders and 222 order lines.

Where it shows. ada_list.html has no script, button, filter or navigation: markup around nine images.

How it breaks the standard. That is a document, the lowest priority deliverable on the bar, though the data would have supported a sortable buy list or a filter for what Fresh does not stock.

What it should have been. A prompt that asks for it: "put the buy list in a table I can sort by aisle or by price".

Catching it in your own task

Ask what the page does when someone clicks it. If nothing, it is a document, whatever the Agent Objective calls it.

What to do instead

Before prompt 1, check the deliverable type against its floor, and have a prompt ask for the interaction the data supports.

1.2 The task relies on records the universe does not holdSee it in the viewer

🔴 Fails the task · Trajectory - Feasibility With Tools

A rule reads off records the assigned universe does not hold, such as a catalog or a policy page, while prompts, inputs and criteria read as if they were there.

Where the correct guidance is written

Guidelines · 1.2.1 Start With the Universe

“The universe combined with the multimodal input has to sustain the opening prompt and every follow-up you intend to add”

Guidelines · 4. Valid vs. Invalid Model Failures

“Data that is not in the server, asked for anyway, and the model penalised for not finding it.”

Listed under “Not valid: your defect, or the platform's”.

QC spec · Trajectory - Feasibility With Tools

“The primary request is impractical or impossible and can't be answered by the tools available or enabled for the task.”

Fails the task when the missing records carry the main request; costs points otherwise.

Example 2 (🔗Open in the viewer)

The task. Five items on a neighbour's board are priced against Amazon Fresh.

Where it shows. Rule 1 prices lines "at the pack option we add to the cart from Fresh's catalog"; rule 5 takes the fee from "Fresh's Delivery Policy and nothing else". The universe's catalog has none of the five items, and its policies are empty.

How it breaks the standard. Leg B turn 3 tells Model B to reach the pages "another way", the golden says "its catalog search returns nothing", and no run can meet the criteria wanting $0.55 a lb or a $4.99 fee.

What it should have been. Rules that cite only records the universe returns, checked before the run.

Catching it in your own task

Your golden shows it: an empty search, a Leg B hint sending Model B another way, figures flagged as unconfirmed.

What to do instead

Before the run, query the universe once per rule and rewrite any rule whose record is missing. If it only surfaces in Leg B, redesign the task rather than hint again.

2. What you may not tell Model A or Model B

Leg A defines the task: the opening prompt and the follow ups you send Model A. Leg B is the golden run: Model B gets the same opening prompt, word for word, then the turns you send it as you steer it through the milestones. The no leak rule and the input folder are the same in both legs; what a turn may point at is not.

2.1 A Leg B hint that hands Model B the answerSee it in the viewer

🔴 Fails the task · Multi-Turn - Simulator Answer Leak

In Leg B, a turn you send Model B hands it what it had to work out: a value, a count, a position or the conclusion. Naming the exact file to open costs points instead.

Where the correct guidance is written

QC spec · Multi-Turn - Simulator Answer Leak

“The user may say THAT something is wrong; they may not say WHAT the right answer is, WHERE exactly to find it, or HOW MANY of anything there are”

Any turn, either leg.

QC spec · Multi-Turn - Simulator Answer Leak

“No graded value is leaked, but the hints narrow the search space beyond an area-level nudge (e.g. naming the exact file to open).”

Costs points. Written about Leg B hints.

Guidelines · 7.2 Steering the Run & Hinting

“The test is simple: if the model can copy your hint into the artifact or use it directly as the reasoning needed to reach the milestone, you have given away the answer.”

Leg B only.

Guidelines · 1.2.3 Create the Initial Prompt and the Follow-ups

“Never flag the miss. If the agent omitted a total, misread a date, or ignored a source, do not tell it what went wrong or where to look. Pointing directly at the failure compromises the 50% failure threshold every task has to meet.”

Leg A only. A punctual correction that comes up naturally is still fine, as long as it does not compromise the 50% failure threshold.

QC spec · Multi-Turn - Turn Structure & Dependency

“Each follow-up must do real work: deliver a withheld asset, extend a requirement, correct an error, tighten a constraint, or answer a clarification the agent asked for.”

About the Leg A follow ups.

Example 3 (🔗Open in the viewer)

The task. Model B still had not opened the day 3 field notes after Leg B turn 8 said they describe PT 128.

Where it shows. Leg B turn 9, to Model B: “Open the day-3 field notes PDF in the mail, the file named 26-014_Field_notes_2026-03-19.pdf”.

How it breaks the standard. Criteria 14 and 2 grade opening that PDF and the card built from it; the golden meets both because the turn named the file. No value is stated, so it costs points.

What it should have been. A hint that leaves the work: “The PT 128 figure on the cedar mound card doesn't match what was actually recorded out there.”

Example 4 (🔗Open in the viewer)

The task. Rule 5 says the building account is not Prime; criterion 30, a -5 negative, catches pricing avocados at the $1.89 Prime price in chat_5D.png.

Where it shows. Leg B turn 7, to Model B: "dont price our order off rosas phone - thats her own account, not the buildings".

How it breaks the standard. That is the conclusion criterion 30 tests, so the golden avoids the trap on instruction. A stated conclusion fails the task in either leg. Model A never got this turn.

What it should have been. Leg B turn 6: "some prices on the page dont look like what fresh charges us", which leaves Model B to find which prices.

Catching it in your own task

For each Leg B turn, ask what is left for Model B to work out. A turn that states what a criterion grades has answered it.

What to do instead

Hint as the user would: say what looks wrong and point at the area, never at the file, the value or the conclusion. If Model B still misses, hint again at the same level.

2.2 A Leg A prompt that answers its own attachmentSee it in the viewer

🔴 Fails the task · Multi-Turn - Simulator Answer Leak

A Leg A prompt that hands Model A a file also states what the file exists to make it read, such as a count or which document is current. The same words in Leg B leak it to Model B too.

Where the correct guidance is written

QC spec · Multi-Turn - Simulator Answer Leak

“One or more user turns supply a value, count, position, or conclusion (see notes for exceptions) the agent was supposed to derive from the multimodal inputs”

Any user turn, in either leg. A count is a value.

Guidelines · 7.1 What Changes from Leg A

“The same intent expressed the same way, and the same persona from first turn to last.”

Unchanged in Leg B, so the turn that hands Model B the file repeats the value.

Example 5 (🔗Open in the viewer)

The task. Leg A turn 2 releases the plates photo, IMG_4392, for Model A to count and measure the plates; Leg B turn 4 releases it to Model B.

Where it shows. Leg A turn 2: "There are five big ones and one small one, and they need to be stored flat somewhere in the unit." Leg B turn 4 sent Model B the same words.

How it breaks the standard. That count is the read IMG_4392 exists to force, so neither model has to open the photo to pass.

What it should have been. The same turn without the count: "They need to be stored flat somewhere in the unit, not stood on edge."

Catching it in your own task

Read each prompt beside the file it hands over, in both legs: any value the model should read from that file is a leak.

What to do instead

State the requirement and leave the value to the file, then run both legs again.

2.3 A deferred asset that announces its own turnSee it in the viewer

🔴 Fails the task · Input Artifacts - Deferred Asset Handling

Something in the input folder, open to both models from turn 1, previews a later turn: a file named for its turn, or a document carrying a later instruction. A file named only for its contents costs points.

Where the correct guidance is written

QC spec · Input Artifacts - Deferred Asset Handling

“The file still ships in input_files/ at upload time, but neither its filename nor any manifest may preview the turn that delivers it.”

Guidelines · 1.2.2 Select the Multimodal Inputs

“All assets must be included in the input .zip folder from the start and use neutral filenames.”

Guidelines · 1.2.3 Create the Initial Prompt and the Follow-ups

“The follow-up must name the asset being introduced so the model knows exactly what new evidence has become available.”

Written for the Leg A follow ups.

Example 6 (🔗Open in the viewer)

The task. The calendar arrives at Leg A turn 2 and the travel rules at Leg A turn 3, both in the input folder from turn 1.

Where it shows. They are named IMG_0814_calendar.jpg and IMG_0819_travel_policy.jpg.

How it breaks the standard. Each name tells both models what is coming before its turn. Nothing graded leaks, so this costs points; a phone would write IMG_0814.jpg.

What it should have been. IMG_0814.jpg and IMG_0819.jpg, with the turns that deliver them saying what each is.

Catching it in your own task

Read the input folder as both models will at turn 1, filenames included: price_sheet_for_turn3.pdf fails, price_sheet.pdf costs points, sheet_02.pdf is fine.

What to do instead

Name deferred files as a phone or scanner would, and let the Leg A follow up that delivers each one say what it is; the Leg B turn repeats it.

3. Milestones

Written from the Leg A conversation with Model A, used in Leg B to steer Model B. Three standards cover what sits around the intent line: Modifier and Assets Delivered, the stopping rules, and one milestone per requirement on every Leg A turn.

3.1 Modifier and Assets Delivered that do not match the Leg A turnSee it in the viewer

🔴 Fails the task · Milestones - Milestone Annotations · Milestones - Continuation Criteria & Assets · most common right now

Modifier or Assets Delivered misdescribes the milestone's Leg A turn: deferred_asset or revision on Leg A turn 1, none as a modifier, a bare extension for a filename, or a deferred file no row lists. Only the last fails the task.

Where the correct guidance is written

Guidelines · 6.1 What a Milestone is Made of?

“Modifier: What this turn does to work that already exists. One of the four in section 6.3. Assets delivered: Files handed over at this turn, or empty.”

This turn is the milestone's Leg A turn.

Guidelines · 6.3 Modifiers

“opening: The first turn and any later turn that adds a new requirement without touching work already delivered. revision: Something already delivered changes.”

Leg A turn 1 is always opening.

QC spec · Milestones - Continuation Criteria & Assets

“Also fails where a deferred asset was handed over during the conversation but is absent from assets_delivered, or is listed but missing from input_files/.”

Example 7 (🔗Open in the viewer)

The task. Leg A turn 2 hands over bourgery_legend_pages.pdf, the one deferred file.

Where it shows. Milestones 1 to 12 all read Assets Delivered: .html, including milestone 9, the deferred_asset row for Leg A turn 2.

How it breaks the standard. A bare extension is not a filename, so the deferred file is listed on no row, which fails the task. The saved input archive lacks the PDF too.

What it should have been. Milestone 9 lists bourgery_legend_pages.pdf, which ships in input_files/.

Example 8 (🔗Open in the viewer)

The task. handbook.mp4 comes with the opening prompt, at Leg A turn 1.

Where it shows. Milestones 7 and 8, both on Leg A turn 1, read deferred_asset and revision, each with Assets Delivered: .mp4.

How it breaks the standard. Nothing is deferred into Leg A turn 1, and Model A has delivered nothing yet for a revision to change.

What it should have been. Both opening, with handbook.mp4 named in full.

Example 9 (🔗Open in the viewer)

The task. Leg A has four turns; the fourth asks for a new list without touching the walkthroughs.

Where it shows. Milestones 1 and 4 read Modifier: none, and milestone 5 sits on turn 5.

How it breaks the standard. None is not a modifier: turns 1 and 4 add work without touching delivered work, so both are opening. Leg A has no turn 5.

What it should have been. Milestones 1 and 4 opening; milestone 5 deleted.

Catching it in your own task

Read Modifier and Assets Delivered beside the Leg A prompts: Leg A turn 1 is opening, and each deferred file sits on the Leg A turn that hands it over.

What to do instead

Set each modifier from what its Leg A turn does to delivered work, and list each file handed over at that turn by full filename, never the deliverable.

3.2 Stopping rules that do not gate the turnSee it in the viewer

🟡 Costs points · Milestones - Continuation Criteria & Assets · Milestones - Milestone Annotations

Continuation criteria, read in Leg B to decide when Model B moves on, either miss one of their Leg A turn's asks or demand what that turn cannot produce, such as a later turn's file.

Where the correct guidance is written

Guidelines · 6.2 Writing the Milestones

“Write one clause per requirement of that turn, separated by pipes, each of them true or false on inspection.”

That turn is the milestone's Leg A turn.

QC spec · Milestones - Continuation Criteria & Assets

“Continuation criteria are present and checkable but under-specified — they would let the simulator advance while a requirement of that turn is still unmet.”

In Leg B, the simulator is you.

Example 10 (🔗Open in the viewer)

The task. Leg A turn 2 hands over the school calendar; the travel rules arrive at Leg A turn 3.

Where it shows. Milestone 8, on Leg A turn 2, asks for the travel rules, with the clause “the travel days in the model reflect only the document the user attached”.

How it breaks the standard. No correct response to Leg A turn 2 can meet it, so in Leg B it keeps you hinting Model B toward a document not yet handed over.

What it should have been. Delete milestone 8; milestone 9 already carries it on Leg A turn 3.

Example 11 (🔗Open in the viewer)

The task. Leg A turn 1 asks, among other things, which pieces still carry a correction.

Where it shows. Milestone 1's six clauses never mention corrections.

How it breaks the standard. In Leg B they let you move Model B on with that ask undone.

What it should have been. Add a clause: pieces carrying a correction are marked as such on their own card.

Catching it in your own task

Could a response skip one of the Leg A turn's asks and still pass? Could a correct one fail for lack of a later file?

What to do instead

Tick every ask in each Leg A prompt against a clause, and move any clause that needs a later file or ask to the turn that brings it.

3.3 A Leg A turn no milestone covers, or the same milestone written twiceSee it in the viewer

🟡 Costs points · Milestones - Continuation Criteria & Assets

A Leg A turn no milestone covers, usually from a set stopping a turn short, or two milestones on one turn with identical intent and clauses.

Where the correct guidance is written

Guidelines · 6.2 Writing the Milestones

“One milestone per requirement, grouped by turn: A follow up carrying three requirements produces three milestones, not one.”

So every Leg A turn has at least one.

Guidelines · 6. Milestones

“you are the simulator, and the milestone set is the only script you have.”

In Leg B, steering Model B.

Guidelines · 6.1 What a Milestone is Made of?

“Turn: Which turn of the Model A conversation the requirement came from.”

Count Leg A turns.

Example 12 (🔗Open in the viewer)

The task. Model A asked which addresses to use for a note to June, and Leg A turn 5, the last, answers.

Where it shows. The milestones stop at Leg A turn 4, so “Use her OPB address, from my Vantol Films account” has none.

How it breaks the standard. Criterion 7 grades both, but no milestone carries them, so a replay against a run that asks, as Model A did, has no script for the answer.

What it should have been. A Leg A turn 5 milestone: the note goes to the address, and from the account, the user named.

Example 13 (🔗Open in the viewer)

Where it shows. Milestones 13 and 14, both on Leg A turn 2, are identical, word for word.

How it breaks the standard. Leg A turn 2's other asks already have milestones, so the copy only repeats a check.

What it should have been. Delete milestone 14.

Catching it in your own task

List each milestone's Turn beside the Leg A prompts: every Leg A turn needs one per ask. Identical neighbours are duplicates.

What to do instead

Write a milestone for each uncovered turn from its prompt, and delete a duplicate or give it its missing requirement.

4. A rubric that separates two runs

A rubric exists to tell a strong run from a weak one. Five standards keep it doing that, and a set can break any of them while still looking complete.

4.1 A rubric that can only reward, never penaliseSee it in the viewer

🟡 Costs points · Rubric Criteria - Overall Rubric Quality · most common right now

Too few negatives for the scenario's traps, so taking the bait costs nothing extra, or a negative worded as the virtue, which marks down correct runs.

Where the correct guidance is written

Guidelines · 5.3 Positive and Negative Distribution

“Negatives are the exception: They should usually make up around 25% of the rubric block and should generally stay below 30%. Use a negative criterion only when it captures a specific, plausible failure mode that the scenario or trajectory meaningfully exposes.”

Guidelines · 5.2 Rubric Weights

“The negative slots are for attractive wrong paths the model has to resist.”

Start with the traps Leg A walked into.

Guidelines · 5.5 Rating Model A and Justifying the Failures

“For negative weight: The trajectory contains the undesirable behavior or boundary violation described by the criterion.”

Example 14 (🔗Open in the viewer)

Where it shows. 24 objective and 10 subjective criteria, every weight positive.

How it breaks the standard. The opening prompt calls the clip's selected answers right, and all three are wrong. A run that trusts them loses only the two +3s of criteria 12 and 19.

What it should have been. “cardio.html keys the self check to the picks selected in 2panels_demo.webm.” Weight −5.

Example 15 (🔗Open in the viewer)

The task. A four and a half minute explainer on an anatomical plate.

Where it shows. A negative at weight −3: “the finished teaching plate remains legible at normal 1080p or full-window playback”.

How it breaks the standard. The golden is legible, so it is Present and loses three points; an unreadable video keeps them.

What it should have been. Weight −3 on the flaw: the plate renders with its captions or labels below legible size.

Catching it in your own task

Negatives should be about a quarter of the set. Present means failure, so a negative describing a good run is inverted.

What to do instead

After Leg A, write a negative for each worthwhile wrong turn Model A took, stating the flaw, never the virtue.

4.2 A requirement nothing grades, and a criterion nothing asked forSee it in the viewer

🔴 Fails the task · Rubric Criteria - Overall Rubric Quality

A prompt requirement no criterion checks, or a criterion no turn asked for, usually written from the golden. Both are Major; a non critical gap, or a criterion that only narrows a real ask, costs points.

Where the correct guidance is written

Guidelines · 5.7 Final Rubric Checklist

“Walk the prompt once per turn and tick off every ask. Anything you can tick needs a criterion.”

QC spec appendix · Rubric Quality Definitions · Incorrect Criteria

“Criterion is not an explicit requirement in the prompt and implementing it makes the response worse.”

QC spec appendix · Rubric Quality Definitions · Missing Criteria - Critical Requirements

“Count each missing rubric that ought to check for an explicit requirement in the prompt or a critical implicit expectation of the prompt as one issue”

A Major issue.

Example 16 (🔗Open in the viewer)

The task. Leg A turn 3 asks for the runbook checked against the cleaning threads, never for a citation.

Where it shows. Criterion 12: runbook_for_cyrus.md names the team's own prior cleaning threads as a source of its rules.

How it breaks the standard. A run that corrects every rule but cites nothing fails it; the golden passes only because it happens to end with a Sources line.

What it should have been. Delete the criterion, and its copy in milestone 11.

Example 17 (🔗Open in the viewer)

The task. Leg A turn 4 says Keep holds only what survives the sheets, Yusuf's email and the calendar.

Where it shows. Only IMG_2201 and IMG_2105 are excluded; nothing says Keep holds nothing else.

How it breaks the standard. Model A's page left IMG_2107 in Keep, which notes.md leaves out of it, and every criterion still passes.

What it should have been. One closure criterion: Keep holds only the items criteria 1 to 10 check for, and nothing else.

Catching it in your own task

Pair each prompt requirement with its criterion, and each criterion with the sentence that asks for it.

What to do instead

Write criteria from the prompt, never from the golden. Where an instruction closes a set, write the closure: X consists only of A, B and C.

4.3 Weights that do not separate difficulty from lookupSee it in the viewer

🟡 Costs points · Rubric Criteria - Overall Rubric Quality

Weights that ignore difficulty: a cross source derivation weighted like a direct read, or one operation at 5 in one row and 3 in the next.

Where the correct guidance is written

Guidelines · 5.2 Rubric Weights

“Weight is difficulty, never importance. How hard the criterion is to satisfy, or for a negative, how tempting the failure is.”

Priced by four axes (source coordination, reasoning depth, modality, discovery effort): three or more is +5, two is +3, zero or one is +1.

QC spec appendix · Rubric Quality Definitions · Incorrect Weights - Major

“Criteria that are objectively incorrectly weighted by two levels, e.g., 1 is selected when 5 is appropriate or vice versa.”

A Moderate issue, despite its name.

Example 18 (🔗Open in the viewer)

Where it shows. Criterion 12, a four step fee derivation across two services, and criterion 17, a PDF page count, both weigh 1.

How it breaks the standard. The score cannot tell a run that found the fee from one that only read page counts.

What it should have been. Weight 5 on criterion 12, 1 on criterion 17.

Catching it in your own task

Count the axes each criterion exercises and read off its weight.

What to do instead

Weight by axis count, never importance. A lookup at 5, or a chained derivation at 1, is a two level miss.

4.4 More trajectory criteria than the Guidelines allowSee it in the viewer

🟡 Costs points · Rubric Criteria - Overall Rubric Quality

More than five criteria target Trajectory. Each is usually sound on its own, so the count creeps up.

Where the correct guidance is written

Guidelines · 5.1 Rubric Fundamentals

“[NEW]: Trajectory Rubrics: Maximum of 5, minimum 0. They are NOT mandatory.”

Since v3, 10 Sep 2026.

Guidelines · 5.4 Category & Evaluation Target

“The agent's reasoning path, Trajectory: An identification, a dependency order, a piece of restraint. The intent it pursued, never a named tool call.”

Example 19 (🔗Open in the viewer)

The task. energy_audit.html splits an electricity bill between two flatmates.

Where it shows. Criteria 33 to 42, ten in all, target Trajectory.

How it breaks the standard. Several grade a route whose result a page criterion already grades, such as 39, that the file runs, beside criterion 1. Criterion 33 only asks the agent to query an application.

What it should have been. Keep five only the run can show, 34, 35, 37, 38 and 42, and drop the rest.

Catching it in your own task

Count the objective rows that target Trajectory.

What to do instead

Keep the five only the run can show, such as a load bearing media read, and move the rest's values into artifact criteria.

Note. The previous version of this course asked for more trajectory weight; Guidelines v3 capped it.

4.5 A run that does not fail enough of the rubricSee it in the viewer

🔴 Fails the task · Hard Client Requirements for Every Task

The criteria Model A fails carry under half the rubric's weight, both blocks counted. Everything looks sound; only the arithmetic shows it.

Where the correct guidance is written

Guidelines · Hard Client Requirements for Every Task

“Model A has to fail: Enough difficulty that the Model A trajectory clearly fails at least 50% of the final rubric score”

Guidelines · 8.5 Rating Against both Models and Justifications

“Rate each subjective rubric as Present or Not Present for Model A.”

So the 50% counts both blocks.

Example 20 (🔗Open in the viewer)

Where it shows. Model A failed 13 of 49 criteria, carrying 43 of the 123 total weight.

How it breaks the standard. That is 35.0%, well under 50%, and the failed rows are already the heavy ones: Model A got most of the task right.

What it should have been. A harder scenario before the run, with sources that disagree; not heavier weights or extra rows.

Catching it in your own task

Divide the weight of the criteria Model A fails by the total, both blocks counted, signs ignored.

What to do instead

Under 50%, make the scenario harder and run both legs again. Never inflate the weights or pad the set.

5. Criteria a correct run can pass

A criterion has to pass a correct run, fail a wrong one, carry the right Category and Evaluation Target, and count once. If your own golden fails one, check the criterion first: it is usually the one that is broken.

5.1 A criterion the golden itself failsSee it in the viewer

🔴 Fails the task · Rubric Criteria - Overall Rubric Quality · most common right now

Your golden fails a criterion that is wrong about the task: a rule only the Desired Outcome states, a phrase at a different length than the golden renders, or a file the inputs archive lacks.

Where the correct guidance is written

Guidelines · 5.7 Final Rubric Checklist

“The golden solution passes the complete rubric set. Anything it fails is a broken criterion, not a broken golden.”

Guidelines · 4. Valid vs. Invalid Model Failures

“A requirement the model never saw. A rubric demanding a heading that appears only in the Desired Outcome.”

Listed under “Not valid: your defect, or the platform's”.

Example 21 (🔗Open in the viewer)

The task. Leg A turn 3 asks for Tamara's exact phrase in the logo: “That truck is a family heirloom at this point.”

Where it shows. Criterion 15: In family_photo_tree.html, the logo shows family heirloom beneath the tree in place of the original word FAMILY.

How it breaks the standard. The turn asks for a sentence and the criterion for two words, so the golden, which renders the sentence, fails.

What it should have been. The logo reads That truck is a family heirloom at this point.

Example 22 (🔗Open in the viewer)

The task. Leg A turn 1 asks which jobs the check cannot clear “because the record is too thin”.

Where it shows. Only the Desired Outcome asks for "Exactly three records". Criteria 24 and 26 grade one of them, "invoice 21-018".

How it breaks the standard. Invoice 21-018 has no job number, so nothing the prompts ask for reaches it, and the golden, which never mentions it, fails both.

What it should have been. Criterion 24 limited to job 14-011 and the ground covered by job 26-004; criterion 26 dropped.

Catching it in your own task

Before you complete Leg B, grade the golden against every objective criterion, and mark every Desired Outcome rule no turn asks for.

What to do instead

Rewrite an unsupported criterion, or fix the golden with a Leg B cleanup turn. Move an outcome only rule into a prompt and run both legs again, or drop it.

5.2 Criteria a correct run cannot pass, or a wrong one canSee it in the viewer

🟡 Costs points · Rubric Criteria - Overall Rubric Quality

A criterion stricter than its source fails correct runs: it pins a figure the source leaves open, picks one answer of several, insists on one of two sources, or scopes to a step that lacks the values. A looser one passes wrong runs.

Where the correct guidance is written

Guidelines · 5.1 Rubric Fundamentals

“Since these are objective rubrics, only requirements that can be evaluated objectively from the scenario should be included.”

QC spec appendix · Rubric Quality Definitions · Overfitting and Underfitting

“Overfitting: Criteria that are overly specific, inflexible or too rigid - they incorrectly reject a subset of valid implementations. Underfitting: Criteria that are overly broad, permissive or loose - they accept valid implementations, but also incorrectly accept invalid implementations too.”

Both are Moderate.

Example 23 (🔗Open in the viewer)

The task. A teaching video's change board scene runs 127.8 to 138.3 seconds.

Where it shows. The criterion is scoped to "The change-board step" and requires "PCR-2026-0688", "accepted on 10 July 2026".

How it breaks the standard. Both appear only in an earlier scene, so the golden is Not Present at weight 5.

What it should have been. Scope it to the video, where both values appear: “source_check.mp4 presents acceptance and release as separate states.”

Example 24 (🔗Open in the viewer)

The task. The voice note asks about "family members who might stay with us", and the records support two.

Where it shows. Criteria 13 and 28 require Aunt Rosalind.

How it breaks the standard. The golden names Tamara Brown-Ellis, whom the records also support, and fails both.

What it should have been. Either answer passes: “combined-home.html identifies a family member from the records as a possible overnight guest and states the recorded need that shapes where they sleep.”

Example 25 (🔗Open in the viewer)

The task. The register prices sit both on a calendar event and in a PDF mailed the night before.

Where it shows. Criterion 26: "The trajectory grounds the nine old and new register prices in the calendar event."

How it breaks the standard. Criterion 29 wants its values from the mail, so a run reading one source fails one of the two; the golden fails 26.

What it should have been. Either source accepted: the calendar event or the price list attached to the 4 May mail.

Catching it in your own task

For each criterion, name its source line and where your golden shows it, then ask what wrong run still passes.

What to do instead

Grade the shape of an answer the source leaves open, accept either source, scope to where the values appear, and add bounds: exactly, only, between.

5.3 Category and Evaluation Target filled with the wrong kind of valueSee it in the viewer

🟡 Costs points · Rubric Criteria - Overall Rubric Quality

Category or Evaluation Target does not fit the criterion: Agent Behavior or Tool Use on an artifact, a category in the target field, or a subjective row tagged Instruction Following.

Where the correct guidance is written

Guidelines · 5.4 Category & Evaluation Target

“Agent Behavior, Target: Trajectory, always. If you wrote Agent Behavior against an artifact, a state change or the final message, you picked the wrong category: you are grading the deliverable, which is Task Completion, Instruction Following or Factuality.”

Guidelines · 8.4 Categories and Evaluation Targets for Subjective Rubrics

“Task Completion is the only valid category for subjective rubrics.”

Example 26 (🔗Open in the viewer)

The task. Criteria 17 and 30 grade what a file states.

Where it shows. Both are Agent Behavior, targeting the artifact.

How it breaks the standard. Agent Behavior always targets Trajectory; a check on what a file says grades the deliverable.

What it should have been. Task Completion, same target.

Example 27 (🔗Open in the viewer)

The task. Subjective criterion 2 grades the key's colours in deltoid_plate_study.html.

Where it shows. It is tagged Instruction Following.

How it breaks the standard. No prompt asks for the colours, so it is a presentation property, and Instruction Following is never valid in the subjective block.

What it should have been. Task Completion.

Catching it in your own task

Read each category beside its target: Agent Behavior and Tool Use only on Trajectory, every subjective row Task Completion.

What to do instead

Retag, do not rewrite: a check on a file takes the deliverable's category, and an explicit ask moves from the subjective block to the objective one.

5.4 The same check written twiceSee it in the viewer

🟡 Costs points · Rubric Criteria - Overall Rubric Quality

Two criteria decided by the same evidence: one inside a broader one, a negative mirroring a positive, or a subjective criterion restating an objective value.

Where the correct guidance is written

QC spec appendix · Rubric Quality Definitions · Overlapping/Redundant Criteria

“Criterion that is either completely redundant because other criteria completely encompass the former or multiple criteria that check for the same thing partly. This can also apply to criteria which have direct semantic overlap with oppositely weighted criteria.”

QC spec appendix · Rubric Quality Definitions · Block Bleed

“A deterministic value check placed in the subjective block, or a presentation judgment placed in the objective block. Count each misplaced criterion. The fix is to move it, never to duplicate it across both blocks.”

A subjective restatement of an objective value is this.

Example 28 (🔗Open in the viewer)

Where it shows. Criterion 2 says the dailies index lists only four files; criterion 9 says two maps are not on it.

How it breaks the standard. If criterion 2 passes, criterion 9 cannot fail: one property, two rows of weight.

What it should have been. Keep criterion 2, drop 9.

Catching it in your own task

Name the evidence that decides each criterion: two on the same line are duplicates.

What to do instead

Keep one, the broader where one swallows the other. A subjective restatement keeps only its presentation property, or goes.

6. The subjective block

Ten or more criteria, no more than 30% of the weight, each grading a property of the render rather than your golden's wording, and each naming its file when the task ships more than one. Check all four before you submit.

6.1 Subjective criteria that never name the fileSee it in the viewer

🟡 Costs points · Rubric Criteria - Subjective Block Scope

Subjective criteria describe features without naming the file that carries them, usually after the first one or two.

Where the correct guidance is written

Guidelines · 5.1 Rubric Fundamentals

“Include the exact expected value, filename, classification, decision, or other fact needed to determine whether it is Present or Not Present.”

8.1 applies it to the subjective block.

Guidelines · 8.1 Writing Subjective Rubrics

“The element makes the criterion self-contained by telling the reviewer where to look.”

With more than one file, that includes the filename.

Example 29 (🔗Open in the viewer)

Where it shows. None of the 10 subjective criteria names a file, and the task ships four.

How it breaks the standard. Criteria 2 and 3 grade marks and columns that both the video and the notes file carry, so graders can score them against different files.

What it should have been. “In move_walkthrough.mp4, passed and failed outcomes are distinguished by colour or a mark, not by wording alone.”

Catching it in your own task

With more than one file, every subjective criterion contains a filename.

What to do instead

Open each one with “In ,”.

6.2 Too few subjective criteria, or too much weight on themSee it in the viewer

🟡 Costs points · Rubric Criteria - Subjective Block Scope

The subjective block holds fewer than ten criteria, or more than 30% of the total weight. Either alone is the error.

Where the correct guidance is written

Guidelines · 8.1 Writing Subjective Rubrics

“The expected number of subjective rubrics is 10 or more, but do not optimize for the count itself.”

QC spec appendix · Multi-Turn Authoring Standards · Writing Subjective Rubrics

“Same weight set {-5, -3, -1, +1, +3, +5}; block capped at 30% of total task weight.”

Signs are ignored on both sides of the division.

Example 30 (🔗Open in the viewer)

Where it shows. The subjective block carries 32 of 103 absolute weight: 31.1%.

How it breaks the standard. Twelve criteria clears the count; the weight alone breaks the cap, however close.

What it should have been. One +5 lowered to +3 gives 29.7%, with almost no margin.

Example 31 (🔗Open in the viewer)

Where it shows. Five subjective criteria.

How it breaks the standard. None looks at the page's cut diagrams or scribe section, so an unreadable diagram scores the same as a clear one.

What it should have been. Ten or more, region by region, each naming front_room_builtin.html.

Catching it in your own task

Count the rows, ten at least, and divide the subjective weight by the total, signs ignored.

What to do instead

Add a criterion for each region nothing grades. Over the cap, add the objective checks your prompts call for, then lower overstated subjective weights.

6.3 Subjective criteria that require your golden's wordingSee it in the viewer

🟡 Costs points · Rubric Criteria - Overall Rubric Quality

A subjective criterion requires the exact heading or label your golden happens to use, words no prompt contains.

Where the correct guidance is written

QC spec appendix · Multi-Turn Authoring Standards · Writing Subjective Rubrics

“Name ONE observable property of the RENDERED artifact. The judge sees the render, not the intent behind it.”

A property, not one build's wording.

Guidelines · 8.1 Writing Subjective Rubrics

“If anything related to the render is asked in the prompt, it requires an objective rubric ONLY.”

A label you chose is graded nowhere.

Example 32 (🔗Open in the viewer)

Where it shows. Criteria 1 and 4 require the golden's own card headings, "Claim 1 - May trip" and "Claim 2 - August trip", and its exact header row, "Claim, Reached your account?, Due by 28 Aug?, and Verdict".

How it breaks the standard. Nine of ten subjective criteria quote words no prompt asks for, so a correct page with its own headings fails all nine.

What it should have been. “In reimbursement_status.html, the two claims are presented as two cards side by side rather than one after the other.”

Catching it in your own task

Search the prompts for every label a subjective criterion quotes. Not found: it grades your wording. Found: it belongs in the objective block.

What to do instead

Name the element by what it is, and grade how it is presented, not what it is called.

7. Closing the task

The golden is a deliverable, not a run you stopped. Check every value against its source and every revision for wording it left behind, then run the close out before you submit.

7.1 The golden states something its own sources contradictSee it in the viewer

🔴 Fails the task · Golden Solution - Artifact Completeness

The golden states a value its source, or its own page, contradicts, often one true at an earlier turn. Nothing graded catches it.

Where the correct guidance is written

QC spec · Golden Solution - Artifact Completeness

“Subjective rubrics and pairwise scoring are graded relative to it, so a defective golden corrupts every subjective score on the task.”

Guidelines · 7. Golden Solution - Leg B

“Every factual claim is grounded in the actual inputs: images opened, videos watched, PDFs read. Nothing is asserted from a filename alone.”

Including the values no criterion grades.

QC spec · Golden Solution - Artifact Completeness

“the golden asserts a finding the inputs do not support.”

One of the shapes that fail the task.

The task. The calendar photo, IMG_0814_calendar.jpg, and the calendar service both give the handover as 18:30.

Where it shows. The golden dashboard: “on-site until 17:00 Fri, can't make the 13:30-15:30 exchange”

How it breaks the standard. 13:30 to 15:30 appears in three places, and the conclusion holds either way, so no criterion catches it.

What it should have been. 18:30 in all three places.

Example 34 (🔗Open in the viewer)

The task. A later turn's photo adds a sixteenth post to the fifteen from the export.

Where it shows. “Two artist-account posts (C16, C17) go out under @sunnyokafor — under P11 not ours to review, so not shown. That's why the count is 15, not 17.”

7.2 A revision that leaves the old wording standingSee it in the viewer

🔴 Fails the task · Multi-Turn - Revision Turn Handling

A revision changes what was asked but leaves wording that depended on it, so the artifact states the old position and the new one.

Where the correct guidance is written

QC spec · Multi-Turn - Revision Turn Handling

“FAIL: both present but contradictory: March rows gone and the flags survived, but the total at the bottom still includes the March amounts.”

Guidelines · 6.3 Modifiers

“The golden has to show the edit applied to work that already existed: earlier content kept, the change visible, nothing left stale that depended on it.”

Example 35 (🔗Open in the viewer)

The task. A late turn moves the newsletter teaser and changes the count from days since filing to days since acknowledgment.

Where it shows. The page still says "The newsletter teaser rides the same Records batch" and "days since filing".

How it breaks the standard. The teaser now sits in two places, and one row still counts from filing while the rest of the page counts from acknowledgment.

What it should have been. The old sentence moved with the teaser, and the row reading "days since acknowledgment".

Catching it in your own task

After each revision turn, search the artifact for every value, label and name that moved.

7.3 The five minute close out nobody runsSee it in the viewer

🔴 Fails the task · Golden Solution - Trajectory Exclusion · Golden Solution - Artifact Completeness · Trajectory - Golden/Preferred Run Selection

Five cheap checks, often skipped: stray files in the golden archive, a filename spelled two ways, a golden that stops early, no starred run, and clauses a grader must decode. The last two cost points.

Where the correct guidance is written

QC spec · Golden Solution - Trajectory Exclusion

“golden/ ships finished artifacts only. The external judge receives the golden ARTIFACTS and never the golden trajectory — anything left in the folder describing how the answer was reached leaks the solution path into grading.”

A caveat about the deliverable stays.

Guidelines · 7.1 What Changes from Leg A

“The preferred run (if multiple exist) must still be marked as ‘Preferred‘ with the star.”

Also in Leg B. A missing star costs points.

Guidelines · 7. Golden Solution - Leg B

“Satisfies every objective requirement, with every required file present and named exactly as requested.”

The prompt's spelling wins.

Guidelines · 1.2.3 Create the Initial Prompt and the Follow-ups

“Contains avoidable grammatical or wording issues.”

A mark of a weak prompt; in a criterion, a Minor issue.

Example 36 (🔗Open in the viewer)

The task. The prompts name three files: baseline_check.mp4, baseline_check_script.md and MEMORY.md.

Where it shows. The golden archive also ships make_baseline_video.py, whose docstring names each answer's "Source of truth".

How it breaks the standard. Five files for three: the script shows how each answer was reached, a quiz image is a renamed copy of an input, and the printable script carries the rebuild instruction.

What it should have been. Only the three named files, none carrying the rebuild instruction.

Example 37 (🔗Open in the viewer)

Where it shows. The prompt names IMG_4508.jpg; the inputs archive holds IMG45.08.JPG.

How it breaks the standard. Any criterion citing the name cannot be scored against the archive.

What it should have been. IMG_4508.jpg everywhere.

Example 38 (🔗Open in the viewer)

Where it shows. Criterion 22 wants a fee of %0.00, and milestone 4 ends "an apartment the sheet doe snot marks keeps all the requests".

How it breaks the standard. The grader has to guess the intended fee, and in Leg B you judge Model B against a sentence that does not parse.

What it should have been. "pantry_audit.html shows a delivery fee of $0.00 for the Mon 6 Jul 2026 order."

Catching it in your own task

Check the archive against the prompts' filenames, the run picker for “Preferred: 1/1 selected”, each filename character by character, each clause read straight through, and the golden reaching the last prompt.

What to do instead

Remove anything not named, clean build notes out with a Leg B cleanup turn, star the golden run, match the prompts' spelling, and rewrite any clause you read twice.

The order that keeps the cost down

  1. Confirm the universe returns every record your rules point at.
  2. Check the deliverable type against the complexity bar.
  3. Build the inputs, then prompts that they and the universe can support.
  4. Run Leg A, write the objective rubric with negatives from Leg A's wrong turns, and rate Model A.
  5. Write the milestones from the Model A conversation, and check them before Leg B.
  6. Run Leg B to the golden. Before you complete it, grade the golden against every objective criterion, check its values and revisions, and fix anything with a Leg B cleanup turn to Model B.
  7. Write the subjective block with the Model A render and the golden side by side, and rate both models.
  8. Run the close out, and confirm Model A fails at least half the weight, both blocks counted.
